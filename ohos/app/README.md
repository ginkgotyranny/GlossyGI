# NCR app for HarmonyOS

The HarmonyOS application that runs NCR on the phone: it loads a scene baked by Falcor and renders and
trains it frame after frame, the hash grids and all passes on the GPU (Vulkan), the two MLPs on the NPU
(NNRt, HiAI Foundation), and shows the result. The frames are those of the runtime in `ohos/replay`
(`replay::Runtime`), the same the command-line replayer runs and checks against Falcor; see
`ohos/README.md` for what the runtime does and how it was verified.

## Layout

```
AppScope/app.template.json5       app.json5 is generated from it (the bundle name comes from the signing)
build-profile.template.json5      build-profile.json5 is generated from it (with the signing)
entry/src/main/ets/               ArkTS shell: EntryAbility (launch arguments, full screen), pages/Index (the XComponent, a status line)
entry/src/main/cpp/app.cpp        native side: NAPI module, XComponent callbacks, render thread, presentation, assets, log
entry/src/main/cpp/CMakeLists.txt libentry.so = app.cpp + ohos/replay/ncr_runtime.cpp
entry/src/main/resources/rawfile/ generated by tools/sync_assets.py (not in git)
tools/                            build, signing, assets, deployment
```

## Building and running

From the repository root, in Git Bash, with DevEco Studio installed (its hvigor, node, ohpm and SDK are
used; `DEVECO_HOME` overrides the location) and the phone connected over hdc:

```bash
python ohos/tools/bake_scene.py bathroom          # Falcor bakes the scene: ohos/_build/scenes/bathroom
python ohos/npu/export_models.py --only inf_256x256 --only _train_4096 --om    # the NPU models, once
bash ohos/app/tools/native_check.sh              # compiles the native library alone (quick check)
bash ohos/app/tools/build_hap.sh                 # assets -> rawfile, signing -> build-profile.json5, hvigor
bash ohos/app/tools/deploy.sh                    # build, install, start, wait 30 s, log and screenshot
bash ohos/app/tools/deploy.sh --no-build --args "--save-at=60" --pull-out 60   # save frame 60's results, bring them back
```

`deploy.sh` leaves the app's log in `ohos/_build/app.log` and a screenshot in
`ohos/_build/app_screenshot.jpeg`; with `--pull-out`, what the app saved in `ohos/_build/app_out`
(`display.bin`, `trained.ckpt`, `schedule.txt`, which `ohos/tools/display_check.py` and
`ohos/tools/train_compare.py` check like the replayer's output).

## Launch arguments

One string, `--name=value` or `--flag`, given by `deploy.sh --args` (`aa start ... --ps args " ..."`);
started from the home screen the app has none and uses the defaults.

| Argument | Default | |
|---|---|---|
| `--scene=<name>` | the first scene in the assets | a folder of `rawfile/ncr/scenes` |
| `--networks=npu\|tiles` | `npu` | `tiles` runs the MLPs on the CPU (for comparisons) |
| `--model=bake\|<path>` | `bake` | the model at the start of the baked frame, or a checkpoint |
| `--train-tile=<n>` | 4096 | samples per training graph; the HAP holds the 4,096 graphs (`sync_assets.py --train-tile`) |
| `--no-train`, `--copy-tiles`, `--cpu-prefix-sum` | | as for the replayer |
| `--loss=<n>` | 0 | print the training loss every n frames |
| `--log-every=<n>` | 30 | per-pass times in the log every n frames |
| `--save-at=<frame>` | 0 | after that frame write `display.bin`, `trained.ckpt`, `schedule.txt` to `<files>/out`; with `--save-results` also every image and ray-batch buffer |

## Signing

A HAP installs only when it is signed, and HarmonyOS debug signatures are made by DevEco Studio for one
bundle name; they cannot be made from the command line. The signing stays out of git:
`tools/gen_build_profile.py`, run by every build, merges `signing.local.json` into
`build-profile.json5` and takes the bundle name for `AppScope/app.json5` from the signing profile.

- Own signature (the app keeps its own place on the phone): run `bash ohos/app/tools/build_hap.sh` once
  (it generates the project files DevEco needs), open `ohos/app` in DevEco Studio, *File > Project
  Structure > Signing Configs*, tick *Automatically generate signature*. The next build moves what
  DevEco wrote into `signing.local.json`. Bundle name `com.example.ncrgi`.
- Borrowed: `python ohos/app/tools/gen_build_profile.py --from <other project>/build-profile.json5`.
  The app then has that project's bundle name, and the two replace each other on the phone.

## On the phone

- Assets: the HAP carries the scene, the shaders and the NPU models in `rawfile/ncr` (about 160 MB for
  bathroom). The first start extracts them to the app's files folder
  (`/data/app/el2/100/base/<bundle>/haps/entry/files/ncr` from hdc's shell) and later starts only
  compare the manifest.
- Log: `<files>/ncr.log`, everything the native side prints; hilog (tag `NCR`) has the same lines but
  drops some.
- The status line on the screen shows the loading steps, then the frame number and time, or the error.
- In the background the render thread neither renders nor trains. When the window's surface goes away
  the swapchain is released first; the device, the runtime and what it has learned stay.
