一、测试方法

测试流程：每个场景对每个算法（ptdn / ptnrd / ncr）独立运行一次 Mogwai。 应用启动后先静置相机 30 秒（warmup，等首帧 shader 编译 / BLAS 构建 / CUDA 初始化完成）， 随后启动相机沿航点轨迹运动，采集 60 秒数据后退出。两轮测试分别对应 useRTXDI=false（round 1）与 useRTXDI=true（round 2）。

RTXDI 开关：useRTXDI 是 PathTracer pass 的运行时选项，通过 Slang shader define USE_RTXDI 在 shader 运行时编译期注入，无需 C++ 重新编译——切换后下次 启动即生效。NCR 不使用 PathTracer，无此开关，两轮结果作对照。

场景与航点：7 个场景各自的相机航点记录在 perf_mem_test/scene_waypoints.txt，通过 BENCH_SCENE 环境变量读取，用 Catmull-Rom 样条插值生成平滑轨迹并循环。 teapot 场景无 pyscene，加载 scene-v4.pbrt。

FPS 采集（定时采样）：渲染回调 sceneUpdateCallback 每帧触发（用于驱动相机）， 但仅每隔 30ms 墙钟时间记录一次帧率样本：FPS = 窗口内帧数 / 窗口时长。 这样无论算法实际帧率高低（ptdn ~50fps 或 ncr ~120fps），采样密度都一致（~33 样本/秒）， 且最小化回调内的记录开销，避免影响实际渲染帧率。汇总采用调和平均 FPS = 总帧数 / 总时长 （从 meta JSON 的 total_frames / wall_time_s 取得，最精确）。

内存采集（nvitop，CPU-MEM + GPU-MEM 同频）：后台线程每 2 秒调用一次 nvitop -1 --ascii --pid <PID>，从进程行同时解析：
· GPU-MEM：进程行 GPU-MEM 列（MiB）；
· CPU-MEM：进程行 %MEM 列 × MemTotal（= 进程 RSS，MB）。
nvitop 对计算（CUDA）与图形（Vulkan）进程均可显示。若 nvitop 未列出进程，GPU-MEM 回退到 nvidia-smi pmon -c 1 -s m（fb 列），CPU-MEM 回退到 /proc/self/status VmRSS。 后台线程方式避免在渲染回调中 fork 子进程。CPU-MEM 与 GPU-MEM 采样频率完全相同（2s）。

内存汇总指标：avg = 测量期内有效采样的算术平均；peak = 测量期内最大值。 Total = CPU-MEM + GPU-MEM。内存波动小，仅以表格汇总，不绘制折线图。

达标判定：
· 帧率：NCR 须比 ptdn/ptnrd 快 ≥50%（即 NCR_fps ≥ other_fps × 1.5），否则该格标红；
· 内存：NCR 总内存须 ≤ ptdn/ptnrd + 200MB，否则该格标红。
差值列 = NCR − ptdn（或 NCR − ptnrd），正值=超出的内存 / 提升的帧率。
